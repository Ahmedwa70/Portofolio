# Ahmed Sobhy — Portfolio Website

موقع بورتفوليو أكاديمي متعدد اللغات لأحمد صبحي، مدرس لغة عربية دولي.
يدعم الموقع **9 لغات كاملة وفعّالة** (لا نصوص جزئية): `en` `ar` `zh` `es` `fr` `tr` `ko` `ja` `id`،
عبر نظام **Multilingual Content Management Architecture** حقيقي — بيانات مترجمة ومخزّنة محليًا،
بدون أي ترجمة آلية أو API خارجي وقت التشغيل.

## كيفية التشغيل
افتح `index.html` مباشرة في أي متصفح — الموقع يعمل بالكامل بدون إنترنت
(لا توجد أي استدعاءات خارجية أو CDN أو خطوط يتم تحميلها من الشبكة).

للتطوير المحلي مع خادم بسيط (اختياري، ويُفعّل تلقائيًا Development Mode — انظر أدناه):
```
python3 -m http.server 8080
```

## المعمارية: فصل صارم بين نوعين من البيانات

### 1) `js/data.js` → `CV_DATA` — كل المحتوى الشخصي
كل ما يخص أحمد صبحي شخصيًا: الاسم، البريد، الخبرات، المؤهلات، المهارات، المشروع، الفلسفة
التعليمية... إلخ. كل حقل نصّي قابل للترجمة مخزّن كقاموس بالبنية:
```js
{ en: "...", ar: "...", zh: "...", es: "...", fr: "...", tr: "...", ko: "...", ja: "...", id: "..." }
```
البيانات التي لا تُترجم تبقى نصًا عاديًا (plain string/array) وليست قاموس ترجمة، وهي:
السنوات (`year`, `period`)، البريد، الهاتف، وأسماء العلامات التجارية (`social.*.label`
مثل `"LinkedIn"`).

**أسماء المؤسسات (`institution`) مترجمة**، مثل `organization` في الخبرات: العربية تحمل
الاسم العربي، والثماني الأخرى تحمل الاسم الرسمي اللاتيني (وهو العرف الدولي لأسماء
المؤسسات، ويسهّل على القارئ التحقق منها). لتوطين اسم في لغة أخرى مستقبلًا، غيّر قيمة
تلك اللغة فقط.

### 2) `js/translations.js` → `UI_TRANSLATIONS` — نصوص الواجهة فقط
عناصر الواجهة العامة القابلة لإعادة الاستخدام بغض النظر عن صاحب السيرة الذاتية: Nav، عناوين
الأقسام (eyebrow/title)، أزرار، تسميات النموذج، رسائل النجاح، شاشة التحميل. البنية هنا
**لغة أولًا**: `UI_TRANSLATIONS[لغة][قسم][مفتاح]`.

**لا يوجد أي محتوى شخصي أو نص واجهة مكتوب مباشرة داخل** `index.html` أو `app.js` أو
`style.css` — كل نص قادم من أحد الملفّين أعلاه عبر دوال مركزية في `app.js`.

## كيف تعمل الترجمة (بدون أي `if (lang === 'ar')`)
كل شيء يمر عبر دالة مركزية واحدة في `js/app.js`:
```js
getLocalizedValue(value, lang)   // لأي حقل من CV_DATA
ui(lang, "nav.home")             // لأي نص واجهة من UI_TRANSLATIONS (مسار بنقاط)
```
تُرجع القيمة الخاصة باللغة الحالية، وإن كانت مفقودة أو فارغة تعود تلقائيًا إلى الإنجليزية
(Fallback)، دون أن تعرض `undefined` أو مفتاحًا داخليًا للزائر أبدًا.

## نظام التحقق من اكتمال الترجمة (Validation System)
عند فتح الموقع في **Development Mode** فقط (عبر `localhost`/`127.0.0.1`، أو فتح الملف مباشرة
`file://`، أو إضافة `?debug` للرابط)، يقوم `app.js` تلقائيًا بفحص `CV_DATA` و
`UI_TRANSLATIONS` بالكامل ويطبع في الـ Console أي ترجمة ناقصة بالشكل:
```
[Translation Warning]
Missing translation:
education[edu4].description
Language: fr
```
هذا لا يكسر الصفحة أبدًا ولا يظهر للزائر العادي — فقط تنبيه أثناء التطوير. حاليًا تظهر تنبيهات
متوقعة لحقول فارغة عمدًا في كل اللغات (وليست ترجمة ناقصة): `personal.cvFiles` (لم تُرفع ملفات
PDF بعد)، و`achievements` داخل كل Experience (محجوزة لإنجازات مستقبلية)، وبعض أوصاف
المؤهلات/الشهادات التي تُركت فارغة عمدًا. أي تنبيه آخر يعني ترجمة فعلية ناقصة يجب استكمالها.

## تعديل المحتوى (المصدر الوحيد للحقيقة)
1. افتح `js/data.js`.
2. غيّر أي حقل — إن كان قاموس ترجمة، عدّل كل اللغات التسع التي تريد تحديثها.
3. احفظ وأعد تحميل الصفحة. لا حاجة لمس أي ملف آخر.

أهم الحقول:
- **البريد/الهاتف/الصورة**: `CV_DATA.personal` (استبدل `photo` بمسار الصورة الحقيقية، و`email`،
  و`phone` — مصفوفة نصوص عادية).
- **ملفات السيرة الذاتية PDF لكل لغة**: `CV_DATA.personal.cvFiles`، مثال:
  ```js
  cvFiles: { en: "assets/cv/cv-en.pdf", ar: "assets/cv/cv-ar.pdf", ... }
  ```
  ضع الملفات داخل `assets/cv/`. زر "تحميل السيرة الذاتية" يظهر تلقائيًا فقط عند وجود ملف
  للغة الحالية، ويسقط (fallback) إلى الإنجليزية إن لم توجد، ويختفي كليًا إن لم يوجد كلاهما.
- **روابط التواصل الاجتماعي**: `CV_DATA.personal.social`.

## تغيير نصوص الواجهة (أزرار، Nav، رسائل النموذج)
افتح `js/translations.js` وعدّل القيمة المطلوبة داخل كتلة اللغة المناسبة في `UI_TRANSLATIONS`.

### ربط نص واجهة بخاصية (attribute) بدل محتوى العنصر
`data-i18n` يملأ نص العنصر. لترجمة **خاصية** مثل `placeholder` أو `aria-label`
استخدم `data-i18n-attr="اسم-الخاصية:مسار.المفتاح"` (وافصل بفاصلة لأكثر من خاصية):
```html
<input data-i18n-attr="placeholder:form.namePlaceholder">
<button data-i18n-attr="aria-label:langSwitcher.label">
```
استثناء واحد: `aria-label` لزر الثيم يُضبط من `app.js` (`updateThemeLabel`) لأنه
يتغيّر حسب الوضع الحالي — يعرض دائمًا الوضع الذي سينتقل إليه الضغط.

## إضافة لغة عاشرة مستقبلًا
1. أضف رمز اللغة إلى `SUPPORTED_LANGUAGES` في أعلى `js/data.js` (مع `dir` الصحيح:
   `rtl` أو `ltr`).
2. أضف مفتاح اللغة الجديد داخل **كل** قاموس ترجمة في `CV_DATA` (استخدم `en` كمرجع للبنية).
3. أضف كتلة كاملة جديدة داخل `UI_TRANSLATIONS` في `js/translations.js` (استخدم كتلة `en`
   كمرجع للبنية).
4. إن كانت اللغة تستخدم خطًا غير لاتيني/عربي (كوري، ياباني، صيني...) قد تحتاج تعريف Font
   Stack مخصص في `css/style.css` (ابحث عن `html[lang="zh"]` كمثال).
5. لا حاجة لمس `index.html` أو منطق `app.js` — القائمة المنسدلة وRTL/LTR يُضبطان تلقائيًا من
   `SUPPORTED_LANGUAGES`.

## RTL / LTR
يتم ضبط `<html lang dir>` ديناميكيًا عند كل تبديل لغة اعتمادًا على `dir` المُعرَّف لكل لغة في
`SUPPORTED_LANGUAGES`. كل التصميم (Grid/Flex/Spacing/Borders) مبني بخصائص CSS منطقية
(`inset-inline-start`, `padding-inline-start`, `text-align: start`...) بدل `left/right` الفعلية،
لذا ينعكس التخطيط تلقائيًا وبشكل صحيح مع العربية دون أي كود إضافي.

### النصوص المختلطة (Bidi)
أي سطر يجمع نصًا عربيًا مع نص لاتيني أو أرقام (اسم مؤسسة + موقع، أو مؤسسة + سنة) يمرّ
عبر الدالة `bdi()` في `app.js` التي تغلّف كل قيمة بوسم `<bdi>` فتُعزَل اتجاهيًا ولا تُعيد
ترتيب ما حولها. القيم المكوّنة من أرقام فقط (`year`, `period`) تأخذ `dir="ltr"` صراحةً،
لأن الأرقام لا تحمل اتجاهًا خاصًا بها، فمدى مثل `2016 — 2026` كان سيظهر معكوسًا
`2026 — 2016` داخل صفحة عربية.

## استمرارية اللغة (Persistence) و`?lang=`
عند اختيار الزائر للغة، تُحفظ في `localStorage` وتظهر أيضًا في الرابط كـ `?lang=xx`
(مثال: `index.html?lang=ja`) عبر `history.replaceState` دون إعادة تحميل الصفحة. عند فتح الموقع:
أولوية القراءة هي **رابط `?lang=` أولًا، ثم `localStorage`، ثم الإنجليزية كافتراضي.**

مع كل تبديل لغة يُحدِّث `app.js` أيضًا وسوم `<link rel="alternate" hreflang>` للغات
التسع + `x-default`، و`<link rel="canonical">` للغة الحالية، و`og:locale` بالصيغة
الصحيحة (`ar_AR` لا `ar`) — كلها مبنية من `SUPPORTED_LANGUAGES` تلقائيًا. تُتخطّى
هذه الوسوم عند الفتح عبر `file://` لأن الروابط المطلقة بلا معنى هناك.

## الهيكل
```
index.html            هيكل الصفحة فقط (data-i18n / data-i18n-cv، بلا نص مباشر)
css/style.css          كل التصميم (Dark/Light، RTL حقيقي، Font Stacks لكل عائلة خط، Responsive)
js/data.js              SUPPORTED_LANGUAGES + CV_DATA — كل المحتوى الشخصي بـ 9 لغات
js/translations.js      UI_TRANSLATIONS — كل نصوص الواجهة بـ 9 لغات
js/app.js               getLocalizedValue / ui / نظام Validation / الرندر الديناميكي / اللغة والـ Theme
assets/images/           الصور (يحتوي حاليًا على شعار أولي بديل للصورة الشخصية)
assets/cv/               (فارغ حاليًا) ضع هنا ملفات cv-en.pdf وcv-ar.pdf... إلخ
```

## ملاحظات لا تزال بحاجة لتحديث من صاحب الموقع
- `personal.phone` فارغة، و`personal.social` كل الروابط فارغة.
- `personal.cvFiles` فارغة لكل اللغات (لا يوجد ملف PDF مرفوع بعد) — لذلك زر
  "تحميل السيرة الذاتية" مخفي حاليًا ويظهر تلقائيًا بمجرد إضافة أول ملف.
- 5 حقول `description` متروكة فارغة عمدًا في `education` و`certifications`.

*(تم بالفعل: `personal.email` بريد حقيقي، و`personal.photo` صورة حقيقية
`assets/images/profile.jpg`.)*
